## Overall Impression

Well-built relative to its own design system, disciplined visual language. The real gap is behavioral, not visual: four consequential actions (Accept, Decline, Cancel, Remove) fail silently in both directions — no success confirmation, and swallowed errors on failure. For a trust-and-consent product between friends, that silence is the biggest opportunity here.

## What's Working

1. Hairline row-list discipline is real, not cosmetic — correctly avoids the "one shadow card per row" anti-pattern DESIGN.md bans.
2. ConfirmSubmitButton's inline confirm is genuinely crafted — stays in-form, focus-to-Cancel, Escape support.
3. FriendRequestForm's error/success handling preserves input on error, clears only on success, documented inline.

## Priority Issues

[P1] Accept/Decline/Cancel/Remove silently swallow their own errors — app/friends/actions.ts:34-57 discard {ok:false, error} returns from lib/friendships.ts. Fix: route through useActionState like sendFriendRequestAction, render error inline on the row. Suggested command: /impeccable harden

[P1] No per-row aria-label on repeated action buttons — Accept/Decline/Cancel/Remove have no name disambiguating whose request each acts on for screen readers. Fix: aria-label={`Accept request from ${req.requesterUsername}`} etc. Suggested command: /impeccable audit

[P2] Friend-request username field has no <label> and no client-side validation — placeholder-only input, unlike UsernameForm's paired label + pattern/minLength one component over. Fix: add label + mirror UsernameForm's pattern="[a-zA-Z0-9_]+" minLength={3}. Suggested command: /impeccable clarify

[P2] No success acknowledgment after Accept/Decline/Cancel/Remove — row just vanishes, most costly on Accept (the moment that should feel warm). Fix: inline role="status" line reusing UsernameForm's pattern. Suggested command: /impeccable delight

[P2] Primary buttons on this page missing the elevation every other primary CTA in the app has — Accept/Send request/Save lack shadow-[var(--shadow-soft)] hover:shadow-[var(--shadow-lifted)] present on login/onboarding/find-time/error/HomeLanding. Fix: add the shadow classes (also applies to /calendars' Share button, same root cause). Suggested command: /impeccable polish
